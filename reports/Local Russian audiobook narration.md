# Choose Russian Narration Through Blind Auditions

Research checked **13 October 2026** for a **Mac M1 Pro with 16 GB unified memory**, with narration quality taking priority over speed. **Start with Qwen3-TTS-12Hz-1.7B-Base through MLX, using a clean native Russian narrator reference.** It is the most defensible first installation for this hardware, rather than a proven winner in Russian audiobook listening. Its released Russian results, cloning workflow, Apache-2.0 weights and Apple Silicon implementation provide a practical foundation. Audition it seriously against **Fish Audio S2 Pro in an 8-bit MLX implementation**, conditional on measured memory fit, and **VoxCPM2 through its official MPS support**. OmniVoice and the Russian F5 specialist are useful additional challengers if the first comparison leaves pronunciation or expression unsatisfactory. Research has not established a controlled listening winner among these exact releases, and this project has **installed no models, generated no samples, performed no listening tests and measured no M1 performance**. The final choice should follow a blinded comparison and a complete chapter test. ([Qwen model card](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base), [MLX-Audio](https://github.com/Blaizzy/mlx-audio), [VoxCPM](https://github.com/OpenBMB/VoxCPM))

## Qwen offers the clearest first experiment on 16 GB

Choose the **1.7B Base** checkpoint rather than treating all Qwen3-TTS variants as equivalent. Base clones a reference recording with its transcript and supports reusable clone prompts; upstream warns that embedding-only cloning can reduce quality. The nine CustomVoice presets have Chinese, English, Japanese or Korean native languages, with no native Russian preset, and upstream recommends using their native language for best quality. A convincing Russian literary narrator is therefore a better starting reference than an English preset asked to read Russian. Qwen's own report gives Russian word error rate, or WER, of **3.212% for 1.7B Base versus 4.458% for 0.6B Base**. This supports starting with the larger Base model when quality matters, without proving a perceptual advantage on books. ([Qwen repository](https://github.com/QwenLM/Qwen3-TTS), [Qwen technical report, Tables 6 and 9](https://arxiv.org/html/2601.15621v1))

The community MLX BF16 conversion displays **4.54 GB of model files**, and its 8-bit counterpart displays **3.1 GB**. These are artifact sizes, **not peak RAM requirements**. Loading, the audio codec, activations, generation caches and macOS all need additional memory. Begin with BF16, short passages and one worker as a quality baseline if actual memory permits; use 8-bit when measured memory or runtime makes BF16 impractical, then compare its output rather than assuming quantization is inaudible. MLX-Audio provides an Apple Silicon implementation, but Russian output parity with upstream remains unverified here. ([BF16 conversion](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-1.7B-Base-bf16), [8-bit conversion](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit), [MLX-Audio](https://github.com/Blaizzy/mlx-audio))

## Fish and VoxCPM2 could win the listening comparison

Fish's current downloadable model is **S2 Pro**, advertised as 4B, with a 4B Slow-AR component, a 400M Fast-AR component and a codec. Its official inference instructions recommend **at least 24 GB VRAM**. Community MLX and int8 implementations make a Mac experiment credible, but do not establish a guaranteed fit on 16 GB shared with macOS. One independent port author reports 10.5 GB peak for int8 on an **M4 Max with 64 GB**, which is evidence about that implementation and machine, not this M1 Pro. Start with one loaded model and paragraph chunks; abandon the configuration if memory pressure or swap makes chapter generation impractical. ([Fish repository](https://github.com/fishaudio/fish-speech), [Official inference guidance](https://speech.fish.audio/inference/), [MLX int8 route](https://github.com/appautomaton/mlx-speech/blob/main/docs/fish-s2-pro.md), [Port benchmark](https://github.com/gafiatulin/fish-speech-mlx))

**Hosted S2.1 Pro is a different release.** Fish's June announcement describes API access to S2.1 and says it builds on the previously open-weight S2. The verified open repository points to S2 Pro; this research did not verify downloadable S2.1 weights. A hosted S2.1 demonstration therefore cannot establish what locally installed S2 Pro will sound like. ([S2.1 announcement](https://fish.audio/blog/s2-1-pro-free-api/), [S2 Pro weights](https://huggingface.co/fishaudio/s2-pro))

VoxCPM2 is particularly worth testing because its upstream implementation explicitly supports **MPS on Apple Silicon**, alongside CPU and CUDA. Its 2B backbone and reported approximately 8 GB GPU-memory requirement make it a credible trial, while leaving actual Mac memory and speed uncertain. Russian is among its 30 supported languages. Its higher speaker similarity in the published multilingual comparison is useful evidence for cloning, but cannot tell us whether its phrasing, stress and emotional delivery suit a novel better than Qwen or Fish. ([VoxCPM repository and evaluation](https://github.com/OpenBMB/VoxCPM))

Larger alternatives such as Higgs TTS 3 and MOSS-TTS-v1.5 have relevant narration capabilities, but their capability claims do not establish a Russian listening win or comfortable 16 GB operation. They belong in a later round if the smaller shortlist disappoints, rather than delaying the first useful comparison. **XTTS-v2 and Silero v5_5_ru are baselines rather than the quality-first default**: XTTS has Russian cloning but no retrieved modern evidence that displaces this shortlist; its CPML restricts both models and outputs to noncommercial use. Silero offers five fixed Russian voices, stress/ё controls and efficient operation, but available historical evaluation also highlights weak intonation. Silero's main Russian weights use CC-BY-NC-SA-4.0. Neither should determine the system merely because existing ebook software supports it. ([Higgs model](https://huggingface.co/bosonai/higgs-tts-3-4b), [MOSS](https://github.com/OpenMOSS/MOSS-TTS), [XTTS license](https://huggingface.co/coqui/XTTS-v2/raw/main/LICENSE.txt), [Silero](https://github.com/snakers4/silero-models), [Silero license](https://github.com/snakers4/silero-models/blob/master/LICENSE), [Historical Russian evaluation](https://alphacephei.com/nsh/2024/07/12/russian-tts.html))

## Russian WER does not measure an enjoyable chapter

Published Russian MiniMax-test results give **2.400% WER for Fish S2**, **3.212% for Qwen 1.7B Base**, and **2.233% for OmniVoice**. VoxCPM2's repository reports **3.634%** on its multilingual comparison. These are author-reported intelligibility/content-fidelity results; cross-paper comparisons are useful for choosing contestants, not a controlled perceptual tournament. Speaker similarity likewise measures resemblance rather than good storytelling. Ordinary ASR can transcribe a word correctly despite wrong lexical stress, and WER does not capture awkward breaths, tiring rhythm, flat dialogue or unpleasant joins. The small numeric lead for OmniVoice does not prove the best audiobook sound. ([Fish report](https://arxiv.org/html/2603.08823v1), [Qwen report](https://arxiv.org/html/2601.15621v1), [OmniVoice report](https://arxiv.org/html/2604.00688v1), [VoxCPM comparison](https://github.com/OpenBMB/VoxCPM))

Chapter reliability is another separate question. Fish and Qwen's published long-form tests concern English/Chinese, not Russian literary chapters. The recent **Balalaika-Longform** Russian study finds substantial omissions and early stopping as uninterrupted generation length increases, but deliberately disables splitting, resets and retries. It conducts no human listening study. Its separate earlier chunked controls show why high continuous-generation error rates must not be used to reject a checked paragraph pipeline; they also use different text sets and cannot establish a cross-model winner. The practical implication is to test the assembled audiobook pipeline, not send an entire chapter through one inference. ([Fish report](https://arxiv.org/html/2603.08823v1), [Qwen report](https://arxiv.org/html/2601.15621v1), [Balalaika-Longform](https://arxiv.org/html/2610.00658v1))

## Preserve book structure and audition the production pipeline

Keep EPUB chapter, scene and paragraph structure when extracting text. Its spine supplies reading order and identifies auxiliary material; flattening everything can duplicate navigation or insert footnotes into unsuitable places. Retain the original text beside a reviewable narration layer, with deliberate rules for notes and foreign quotations. Normalize numbers, dates, initials, abbreviations and Roman numerals only into their intended spoken forms. Maintain a per-book pronunciation dictionary for recurring names. These are proposed engineering choices; no user EPUB has been inspected. ([W3C EPUB 3.3 spine specification](https://www.w3.org/TR/epub-33/#sec-spine-elem))

Russian **stress and е/ё require contextual checking**. RUAccent offers local stress prediction, homograph disambiguation and ё restoration, but its accuracy is imperfect and its `+` output convention is not a universal TTS input format. Explicit `+` stress is documented for the Russian F5 checkpoint and Silero. Test raw text, ё-corrected text and selective supported stress hints separately for each shortlisted runtime; reject hints that are ignored, spoken literally or spoil cadence. Never silently paraphrase literary prose to conceal synthesis problems. ([RUAccent paper](https://aclanthology.org/2025.coling-main.444.pdf), [RUAccent implementation](https://github.com/Den4ikAI/ruaccent), [Russian F5](https://huggingface.co/Misha24-10/F5-TTS_RUSSIAN), [Silero SSML](https://github.com/snakers4/silero-models/wiki/SSML))

The first experiment should use **12–20 matched excerpts** from the actual book types: ordinary exposition, emotional dialogue, long syntax, questions, names, numerals, homographs and ё cases. Freeze checkpoint/runtime/settings and use the same clean Russian reference source with an accurate transcript where supported. Preserve first attempts to count failures; allow an equal predefined retry budget in a separate production-quality comparison. Randomize blind labels and match loudness without changing speed. Have the user, ideally with additional native Russian listeners, score naturalness, stress, phrasing, voice consistency and sustained comfort. Ask which narration they want to hear for an hour.

Then render the same **20–30-minute chapter with the preferred two configurations**. Begin with coherent sentence groups or paragraphs, comparing proposed 20–40-second and 45–90-second chunks rather than arbitrary character cuts. Keep the narrator reference fixed. Check omissions, additions and repetitions using independent ASR/alignment, then listen manually for pronunciation and joins. Record peak memory, swap, render time and retries per audio hour. Run accent preparation, TTS and ASR sequentially to preserve memory headroom. Save lossless chunk masters and a manifest so failed passages can be regenerated individually before chaptered M4B export. These are test parameters, not measured optimums.

## Conclusion

The decisive next step is a small local comparison that exposes both preference and production failures. Qwen Base 1.7B gives this Mac a defensible starting point; Fish S2 Pro and VoxCPM2 give it serious opportunities to improve narration. The winning system will be the checkpoint, narrator reference and text/chunking workflow that sound best while preserving the book accurately across a chapter. Faster generation matters only after that combination fits the machine and earns the user's listening preference.
